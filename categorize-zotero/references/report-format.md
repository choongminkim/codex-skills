# Categorization report

Present one concise entry per item before changing Zotero. A chat report is sufficient unless a report file is requested; resolve its destination before saving a file.

```text
Title:
Zotero item key:
Citation key:
Obsidian note:
Read basis: final Obsidian article note | missing note | explicitly requested metadata fallback
Note Category:
Primary collection:
Secondary collections:
New collections needed:
Confidence: High | Medium | Low
Reason:
Proposed Zotero changes:
- Create top-level collection ... (if needed)
- Add item to ...
- Remove item from source collection: yes/no
Needs user decision:
```

Include an alternative only when a meaningful ambiguity needs resolution. Paraphrase evidence; do not quote long passages. Distinguish additions from removals so the user can approve all, selected items, or revised destinations.

- High: the final note's Category and summary clearly support the destinations.
- Medium: the primary domain is clear but secondary membership or naming is debatable.
- Low: evidence is incomplete or the primary domain is ambiguous. A missing note is unresolved, not grounds for an invented low-confidence classification.

## Optional preview fields

Include these only for a requested preview review or cleanup:

```text
Preview note:
Preview cleanup readiness: Ready | Not ready
Reason / unmet gates:
Proposed preview cleanup: Move <exact source> -> <exact destination> | Keep
```

For readiness-only review, no trash path is required and no move is proposed. Distinguish note readiness from eligibility to move: classification writes or source removal may still be pending. Resolve the trash path and present exact moves before obtaining cleanup approval. Do not request cleanup approval merely because classification was requested.
